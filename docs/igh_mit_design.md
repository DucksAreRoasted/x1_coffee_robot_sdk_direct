# IgH 后端的 MIT 模式设计

目标：在 IgH 传输层上跑通 eRob 的 CST（周期同步力矩）模式，供右臂 MIT 手感/阻抗使用。
复用 `SoemEthercatTransport` 已有的 MIT 策略，不另写一套。

## 一、现状与缺口

完整 PDO 已经能跑（Rx 10 字节 / Tx 16 字节，工作计数 45/45，实机验证过），
所以 **MIT 不需要改总线映射**：

| 方向 | 对象 | 用途 |
|---|---|---|
| Rx `0x1600` 第 3 项 | `0x6071` 目标力矩 | MIT 发力矩 |
| Tx `0x1A00` 第 4 项 | `0x6077` 实际力矩 | 观测、限幅 |
| Tx `0x1A00` 第 5 项 | `0x6078` 实际电流 | 观测、模型辨识 |

`IghEthercatLink` 里还留了三个缺口：

1. `requestDriveMode()` 是空实现，只打印「暂不支持」
2. `copyRatedTorqueNm()` 没实现，`rated_axis_nm_` 全 0
3. 没有 `0x6061` 模式读回，切模式是否成功无法确认

## 二、运行时切模式的时序

IgH 只能用 `ecrt_master_sdo_download()`，它是**异步**的：请求进邮箱队列，
由内核 OP 线程执行，调用方不能同步等。在 1 ms 周期线程里同步等会拖慢周期帧，
触发 SM 看门狗，从站报 `0x001B` 回到 SAFEOP（迁移过程中实测过这个后果）。

所以拆成三拍：

```
控制线程          requestDriveMode(CST, mask)  →  记录 pending_mask_
   ↓
周期线程          取 pending_mask_，调 ecrt_master_sdo_download(0x6060, 0x0A)
   ↓              （IgH 内部排队，不阻塞本拍）
周期线程          读回 PDO 里的 0x6061，与期望模式比对
   ↓              全部一致 → 置 mode_confirmed_
上层              只有 mode_confirmed_ 才允许发力矩
```

约束：

- 每次只切一个轴，失败不影响其他轴
- 切换超时（默认 100 拍 = 100 ms，可配）判定失败
- 切换期间 `0x6071` 必须持续写 0，不能沿用上一拍的力矩

## 三、额定力矩读取

MIT 的力矩换算依赖 `0x6076`（mN·m）。IgH 没有「配置期读 SDO」接口，只能在
`ecrt_master_activate()` 之后、放开使能之前，用 `ecrt_master_sdo_upload()` 逐台读。

规则：

- 读不到或长度不是 2/4 字节 → 该轴标记为 `rated_unknown`，**禁止进入 MIT**
- 读到之前 `bus_operational_` 保持 false，上层不会放开使能
- 读数落日志，便于现场核对

## 四、安全门与回退

进入 MIT 的前置条件（全部满足才放行）：

1. 15 台都在 OP，工作计数 45/45
2. 15 轴状态字 `0x0027`（已使能）
3. 15 台 `0x6061` 都已确认切到 `0x0A`
4. 额定力矩已读到
5. 反馈新鲜（距上一拍 < 100 ms）
6. 无报警、无跟随误差、无急停输入

回退（任一条触发）：

- 切模式失败或超时 → 该轴保持 `0x6071 = 0`，其余轴回 CSP
- 运行中模式读回不符期望 → 立即回 CSP，目标位置设为当前实测
- 报警/急停 → 走既有 `stop(true)` 路径，发 `0x0006`

**不允许**在同一拍里既发力矩又改目标位置；两套语义互斥，靠 `mit_active_` 单点判定。

## 五、默认范围与限幅

- 范围：先完成设计与右臂 7 轴框架，`mit_mask_ = 0x7F00`（沿用现有），实机验证从单轴开始
- 进入 MIT 前手臂必须有重力补偿或机械支撑，**不允许自由下坠**
- 力矩限幅沿用现有 `mitTorque()` 的额定力矩千分比算法，不改成绝对 N·m

## 六、分步落地

| 步骤 | 内容 | 验证方式 |
|---|---|---|
| 1 | link 补 `requestDriveMode` 排队 + `0x6061` 读回 + `copyRatedTorqueNm` | 下位机编译 + 单测（假 link） |
| 2 | 启动阶段读 `0x6076`，读不到拒绝进 MIT | 实机日志核对额定力矩 |
| 3 | 单轴切 CST 并确认，目标力矩恒 0 | 实机：`0x6061` 变为 0x0A，手臂不动 |
| 4 | 单轴施加小力矩（≤5% 额定），观察 `0x6077` | 实机，操作者在场 |
| 5 | 右臂 7 轴 MIT 手感 | 实机，需支撑或重力补偿 |

第 3 步之前不涉及真实力矩输出，可以在无人值守时做；第 4 步起必须有人在场。

## 七、已知限制

- IgH 的 `ecrt_master_sdo_download()` 依赖邮箱，切换期间总线会多出邮箱流量，
  切换应只在「已使能且稳定」后进行，不在 1 ms 启动阶段做
- 该接口的返回值只表示「请求已排队」，不代表驱动器已接受，必须以 `0x6061` 读回为准
- 力矩模式下 SM 看门狗仍按 100 ms 生效，周期抖动过大时驱动器会报 `0x001B`

## 八、零力矩 CST 验证入口（第 3 步的实现约定）

现有的键盘 `m m` 走 `enterMitHandfeel()`，会按 kp/kd 算力矩并弹簧回正，
属于第 5 步的验证范围，不能用来验证「模式切换」本身。因此单独加一个入口：

- `GtnTransport` 增加虚函数 `enterCstZeroTorque(std::uint16_t axis_mask)`，
  默认返回不支持，IgH/SOEM 传输层各自覆盖
- 行为：对该 mask 的轴调用 `requestDriveMode(0x0A, mask)`，并在周期里把这些轴的
  `0x6071` 恒写 0，**不接任何 kp/kd**
- 不改 `0x607A`，位置轴的目标位置保持锁存，退出时回到 CSP 并重新对齐实测
- 服务名 `/x1/mit_zero_check`，参数为轴掩码，默认 `0x00FE`（左臂）或 `0x7F00`（右臂）

实现约定（2026-11-11 落地）：

- `Trigger` 服务没有请求字段，掩码改用节点参数 `cst_zero_mask` 给：
  `ros2 param set /x1_coffee_system_hardware cst_zero_mask 16384`（`0x4000`）只切 r7 单轴。
  调用一次切入，再调用一次退出。默认值仍是 `0x7F00`，**全右臂同时零力矩会掉臂**，
  实机第一次必须用单轴，且手臂有支撑或人扶。
- `GtnTransport::cstZeroStatus(mask)` 读回 `0x6061`、状态字、`0x6077` 千分比和
  `0x607A`−`0x6064` 的脉冲差；服务在请求后最多轮询 1 s 并把读回写进响应 message。
  判据 1 和 4 以这条读回为准，不再只看「已请求」。
- 退出路径先把 `0x607A` 重新对齐退出瞬间的 `0x6064` 再切回 CSP；CST 期间被重力
  带偏的轴不会按旧目标猛拉。`soem_ethercat_transport_test` 里有对应回归用例。

实机结论（2026-11-11，单轴 r7 / r2 / r3 / r5 与 r2+r3 双轴）：

- 四条判据全部成立：`0x6061` 0x08↔0x0A、`0x6077` ≈ 0‰、`/joint_states` 最大变化
  6.0e-5 rad、退出 Δ脉冲 ≤ ±4（≈5e-5 rad）。
- **承载轴不能用零力矩试**：r6（保持 +86‰）切 CST 后 2 s 内被重力带走 0.12 rad，
  随后驱动器报 `0x1288`（状态字 bit3 故障、bit7 警告），轴 14 需要现场断电重上电。
- 该故障暴露了零力矩路径的一个缺陷并已修：CST 期间 `0x607A` 原先停在进入时的锁存值，
  关节被带走后驱动器按旧目标累积位置误差。现在 `onCycle` 对 MIT 和 cst_zero 轴
  一律把 `0x607A` 贴着 `0x6064`，和 MIT 分支同一处理。
- 承载轴（r1/r4/r6）或整臂 `0x7F00` 要在有重力补偿或机械支撑的前提下重做，
  且必须先确认 `0x1288` 的触发阈值，别再靠人扶硬扛。

第 4 步入口（小力矩）：

- 传输入口改为 `enterCstZeroTorque(mask, torque_permille)`，`torque_permille` 是
  额定千分比的常数偏置，只作用于掩码内轴，默认 0 保持「纯模式切换」语义。
- 服务参数 `cst_zero_torque_permille`（默认 0）。传输层与节点各夹一次 ±50‰（额定 5%）；
  非零力矩要求掩码只有一个轴，多轴直接拒绝。
- 退出时偏置清零，`0x6071` 回到 0。

验收判据（缺一不可）：

1. 目标轴 `0x6061` 从 `0x08` 变为 `0x0A`
2. 目标轴 `0x6077` 实际力矩接近 0（< 额定力矩 1%）
3. 手臂完全不动：`/joint_states` 最大变化 < 0.001 rad
4. 退出后 `0x6061` 回到 `0x08`，目标位置等于退出时的实测值

只有这四条都满足，才允许进入第 4 步（施加 ≤5% 额定力矩）。
