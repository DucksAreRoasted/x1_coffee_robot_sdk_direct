## 功能目标

让已有的 `test_startup_motion.py` 被 `colcon test` 执行。该文件使用标准库 `unittest`，并用假节点检查启动脚本。本任务不改启动状态机。

## 输入依据

- `src/x1_coffee_integration/test/test_startup_motion.py`
- `src/x1_coffee_integration/CMakeLists.txt` 目前没有 `BUILD_TESTING`
- `AGENTS.md` 已指出该测试未挂进包

## 接口契约

不改变 `robot_startup.py` 的参数、话题和运动请求。测试失败时不得在本任务里修改启动脚本。

## 实施范围

用 `ament_add_test` 或等价方式，在测试阶段运行：

```bash
python3 src/x1_coffee_integration/test/test_startup_motion.py
```

工作目录和 `PYTHONPATH` 必须让该文件继续用相对路径找到 `scripts/robot_startup.py`。

## 允许修改的文件

- `src/x1_coffee_integration/CMakeLists.txt`
- `src/x1_coffee_integration/package.xml`（仅当缺少 `ament_cmake_test` 之类的测试依赖）

## 禁止修改的范围

- `scripts/robot_startup.py`
- `vendor/gtn`、标定 yaml、传输层、手册

## 测试方案

```bash
source environment/scripts/setup_sdk_environment.sh
source install/setup.bash
colcon test --packages-select x1_coffee_integration --event-handlers console_direct+
colcon test-result --verbose
```

同时直接运行一次 `python3 src/x1_coffee_integration/test/test_startup_motion.py`，两个命令的退出码都要记录。

## 验收标准

`colcon test` 的结果里出现该测试，且退出码为 0。`robot_startup.py` 的 diff 为空。

## 风险及回滚

若现有 unittest 本身失败，本任务停在失败记录，不把启动脚本改到测试通过。回滚时还原 `CMakeLists.txt` 和 `package.xml`。
