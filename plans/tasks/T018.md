# T018 返回值 -10 的分支

- 所属模块：Transport
- 初始状态：BLOCKED
- 前置依赖：T006
- 类别：实现任务。若 T006 的证据来自实机，该次取证本身需要授权；本任务的软件修改仍只用注入的 `GtnNativeApi`

## 功能目标

在同一次具体调用上，-10 的含义被唯一确定之后，才为该调用增加对应的 `CoreError` 细节。总表里的“主机通讯失败”和 InitEcat 的“未找到从站”继续并列，直到 T006 分开它们。

## 输入依据

`specs/unresolved.md` 的 C6，以及 `specs/protocol_spec.md` 第 4.1、4.5 节。-14 同样有总表和 SDO 两种原文，本任务不单独挑选。

## 接口契约

`CoreError` 的现有数值保持不变。阻塞期间不新增错误码枚举。解除后，细节字符串必须引用 T006 所限定的函数名，不能让所有返回 -10 的路径共用一句“未找到从站”。

## 实施范围

阻塞期间不改 `nativeFailure` 或调用点。

## 允许修改的文件

阻塞期间无。解除后只允许 `production_gtn_transport.cpp`、其头文件和 `production_gtn_transport_test.cpp`。

## 禁止修改的范围

- `hardware_types.hpp` 里已有枚举值的数值
- `gtn_native_api.*`
- 启动脚本对 -10 的界面文案，除非 T006 明确写的是那一层

## 测试方案

注入 API 让被 T006 点名的函数返回 -10，断言细节与该函数的已选含义一致。再让另一个仍有冲突的函数返回 -10，断言它不会被写成同一种含义。不打开真实板卡。

## 验收标准

T006 未区分调用点时，传输层无 diff。区分之后，测试退出码为 0，且未区分的调用点仍然不会返回“未找到从站”或“PCIe 被占用”中的固定一句。

## 风险及回滚

把操作说明里的“PCIe 忙”写成全部 -10 的原因，即任务失败。回滚时恢复三个允许的文件。

## 阻塞原因

依赖一次真实出现的 -10 或 -14。C6 仍是 CONFLICT。2026-10-28 现场决定不再专门复现这两个返回值；遇到具体调用返回它们时再记函数名和含义。在那之前不改传输层。
