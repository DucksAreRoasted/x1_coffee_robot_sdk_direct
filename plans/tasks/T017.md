# T017 通用故障复位

- 所属模块：Device SDK
- 初始状态：BLOCKED
- 前置依赖：T007

## 功能目标

只有新证据写出通用故障复位字时，才把 `/x1/safety/fault_reset` 接到驱动器。当前真实后端保持失败。`0x6040=0x80` 只属于“多圈关节不接电池、当单圈使用”的场景，不能当成该服务的实现。

## 输入依据

- `specs/protocol_spec.md` 第 4.4 节和第 8.4 节末段
- `specs/sdk_api.md` 第 3.4 节：真实后端未实现时 `accepted=false`
- `src/x1_coffee_device_sdk/src/safety_service_server.cpp` 的现有失败路径

## 接口契约

`SafetyCommand` 的命令值 3 保持不变。`simulate=false` 时继续 `accepted=false`，直到通用复位字有唯一原文。bit7 上升沿是 VERIFIED 的位定义，但完整控制字 0x80 以外的其他位没有被步骤表写成 0，不能自行补齐。

## 实施范围

阻塞期间不改安全服务器。解除后也不得调用 `GTN_AlarmOff`，不得在原因仍在时调用 `GTN_ClrSts`。

## 允许修改的文件

阻塞期间无。解除后只允许安全服务实现及其测试，且服务名保持 `/x1/safety/fault_reset` 与 `/x1/safety/command`。

## 禁止修改的范围

- `SafetyCommand.srv` 的字段和取值
- 传输层里的报警屏蔽
- `0x4602` 刹车对象。使能中禁止写

## 测试方案

现有失败路径由 T001 锁住。解除后的测试使用注入 API，断言复位命令与新原文的字节一致，并且 `simulate=false` 在没有传输时仍失败。

## 验收标准

阻塞期间 `safety_service_server.cpp` 无 diff。解除后，测试名称能对应到新来源的页码；仅凭 V3.43 的 0x80 特殊场景不得让真实服务返回成功。

## 风险及回滚

把 0x80 或 `GTN_ClrSts` 接成通用复位，即任务失败。回滚时恢复安全服务源文件。

## 阻塞原因

依赖 T007。现有手册没有通用复位字。
