# T014 夹爪 Modbus 客户端

- 所属模块：Device SDK
- 初始状态：BLOCKED
- 前置依赖：T008

## 功能目标

在 Modbus 手册给出功能码、寄存器、站号和波特率之后，再实现夹爪读写。现有 `GripperCommand` 与 C++ 话题发布保持不动。

## 输入依据

`specs/protocol_spec.md` 第 2.3 节和 `specs/unresolved.md` 缺口第 9 条。`specs/sdk_api.md` 写明 C++ 与 Python 是两条已发布入口。

## 接口契约

阻塞期间不增加串口客户端。解除后的新类型不得替换 `GripperClient` 的构造签名。真实状态仍须读到实际位置；没有状态则超时并 abort，这条现有行为保持。

## 实施范围

T008 未给出寄存器表时，不新增源文件。

## 允许修改的文件

阻塞期间无。解除后只允许新的 Modbus 源文件、其测试，以及把测试注册进对应包。不允许改 `gripper_client.hpp` 的公开构造函数。

## 禁止修改的范围

- 左右 `gripper_cmd` 动作名
- `SafetyCommand.srv`
- 传输层与标定
- 不得把开度 0–1000 或力 20–100 写成 Modbus 寄存器

## 测试方案

解除后用注入的串口替身断言功能码和寄存器与手册页一致。不打开 USB 设备。

## 验收标准

阻塞期间夹爪源码无 diff。解除后，测试向量中的每个寄存器都能指到 T008 登记的页码，且旧的 `move_to` 测试仍然通过。

## 风险及回滚

用 8 秒等待或 USB 7/8 编号编成站号和波特率，即任务失败。回滚时删除新客户端。

## 阻塞原因

依赖 T008。Modbus 手册不在 `manual/`。
